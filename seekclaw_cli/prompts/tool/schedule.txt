Create or manage scheduled follow-ups after the user requests recurring work or later continuation. Default to continuing the current conversation and notify only on meaningful changes. Save self-contained instructions describing what to check, when to report, and when to stop. Use a five-field cron expression in the host's local time zone. Each run inherits current project permissions; unattended actions requiring approval fail closed. Use complete to disable a follow-up once its stopping condition is met. Standalone schedules create a new conversation per run. Never claim a local schedule can run while its daemon is stopped. Successful changes return an interactive task card with schedule details and controls; briefly confirm the outcome in prose without copying the full JSON or inventing card markup.
