Control the visible browser embedded in SeekClaw Desktop's side panel. It belongs to this conversation, with its own tabs and cookies, separate from the user's regular browser. Actions show a visible AI virtual cursor in the browser viewport and never move the system pointer or activate another app. Prefer this tool for browsing over desktop computer tools.

Start with open(url) or tabs. Read snapshot before acting; element_id and snapshot_id must come from the latest returned snapshot. Supported interactions: click, right_click, double_click, hover, drag (element_id -> target_element_id or x/y -> to_x/to_y), fill (input/textarea/contenteditable/<select>), select_option (<select> value or label), scroll (delta_y), and press (including combos like Ctrl+A, Ctrl+C, Ctrl+Shift+Z). Use evaluate(script) to run JavaScript expressions or async blocks directly in the page context, and use console/network to inspect console messages or HTTP requests/failures.

For camera, microphone, geolocation, notifications or file downloads, call request_permission(permission, reason) or download(url, filename, reason) — or trigger the page prompt — which presents SeekClaw Desktop's approval popup so the user can allow or deny explicitly. Do not attempt downloads or permission-gated actions without the user's task authorization. Only HTTP(S), including local development servers, is supported. Use a new snapshot after navigation; never guess stale element IDs.
